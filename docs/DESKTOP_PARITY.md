## 2026-10-12 备份导出保护与操作时序

- 导出不再直接以 outputStream 截断现有文件，改由 writeBackupAtomically 使用 AtomicFile 写入；序列化失败和提交前取消恢复旧备份，新文件失败不保留半份目标文件。拒绝将同名目录当作备份文件替换；旧版 AtomicFile 若在移动 .bak 后创建描述符失败，尝试通过 openRead 恢复。序列化器关闭 BufferedWriter 时仅 flush 借用输出流，由 AtomicFile 负责同步和关闭实际描述符。
- 输出包装流按字节块直接写底层，不使用 FilterOutputStream 默认逐字节循环；每次输出检查协程取消。AtomicFile.finishWrite 的某些重命名错误只记录日志，提交后对最终文件和已输出字节的 SHA-256 作比较，不在旧文件仍保留时错误报告成功。校验和磁盘读写均在后台执行。
- 新增 BackupOperationRunner，提交时 compareAndSet 取得忙碌标记，避免 IO 协程启动前的重复提交窗口；所有完整/歌单导出、备份/LX 解析、恢复及 LX 导入共用。后台工作与 UI 回调分开，忙碌涵盖结果反馈；作用域取消不变成“导入失败”回调，已取消作用域也不留下永久 busy。歌单 ID 在派发前快照。
- 新增文件测试在 Android 28/35 各跑 5 项：目录保护、旧文件失败回滚、新文件失败清理、UTF-8/序列化器关闭/再次写入、取消不提交；操作控制 4 项覆盖即时忙碌和重复阻止/线程/回调期间状态、失败后再次提交、进行中取消、已取消作用域。全部 336 项测试、Debug APK 构建及 git diff --check 通过，日志 build/backup-operations-validation.log。
- 测试明确记录宿主差异：Robolectric 在 Windows 执行新版 AtomicFile 的 Java rename，无法像 Android 的 POSIX rename 一样覆盖已存在目标；API35 再次写入分支验证报告 IOException 且旧备份保留，不能将其宣称为 Android 35 设备成功覆盖。提交失败时新版暂存 .new 可能保留，后续 AtomicFile 写入可复用；真实设备上的覆盖、断电恢复及全部文件选择器流程继续验证。导出保护不等于整库恢复事务，歌曲/主题与整库回滚仍待完善，整体目标进行中。

## 2026-10-12 歌曲库恢复事务与 LX 身份一致性
